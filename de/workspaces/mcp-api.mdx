description: "Verbinde Claude Desktop, Cursor oder einen beliebigen MCP-kompatiblen KI-Client mit deinem Genie-Workspace. Erstelle Projekte, sende Prompts, verwalte Mitglieder und frage den Verbrauch ab — alles programmgesteuert über OAuth 2.0."

Der Genie MCP Server ermöglicht es externen KI-Clients — Claude Desktop, Cursor, eigenen Agenten — sich mit deinem Genie-Workspace zu verbinden und ihn programmgesteuert zu verwalten. Einmal verbunden, kann die KI Projekte aus Prompts erstellen, Folgeanweisungen senden, den Build-Verlauf durchsuchen, Mitglieder verwalten, den Credit-Verbrauch abfragen und mehr — alles über dieselben Tools, die die Genie-Web-App verwendet.

<Note>
Der Genie MCP Server ist in allen bezahlten Genie-Tarifen verfügbar. Jede Verbindung ist über OAuth 2.0 auf einen einzelnen Workspace beschränkt. Nur die Tools, die deiner Rolle in diesem Workspace entsprechen, sind zugänglich.
</Note>

## Client verbinden

### Endpunkt

```
https://www.genie-app.de/api/mcp
```

Der Server verwendet den **Streamable HTTP** MCP-Transport (`POST`, `GET` und `DELETE` auf derselben URL).

### Authentifizierung

Der Genie MCP Server verwendet **OAuth 2.0 mit PKCE**. Jede Autorisierung ist auf einen einzelnen Workspace beschränkt — du wählst, welchen Workspace du während des OAuth-Flows autorisierst, und jeder Tool-Aufruf ist auf diesen Workspace beschränkt.

Die meisten MCP-Clients (Claude Desktop, Cursor) verwalten den OAuth-Flow automatisch, wenn du die Endpunkt-URL in ihre Einstellungen einfügst und ein Gespräch startest. Der Client erhält ein kurzlebiges Token, das Genie automatisch erneuert.

### Beispiel: Claude Desktop

Füge den folgenden Eintrag zu deiner `claude_desktop_config.json` hinzu:

```json
{
  "mcpServers": {
    "genie": {
      "url": "https://www.genie-app.de/api/mcp",
      "transport": "streamable-http"
    }
  }
}
```

Starte Claude Desktop neu und öffne ein beliebiges Gespräch. Claude wird dich beim ersten Aufruf eines Genie-Tools auffordern, die Genie-Verbindung zu autorisieren.

### Projekt-Code-Graph

Stelle Fragen zum eigenen Code eines Projekts — nützlich für einen externen KI-Client, der ein Projekt verstehen muss, bevor er es ändert oder Fragen dazu beantwortet.

| Tool | Was es tut |
|---|---|
| `query_project_code_graph` | Stelle eine natürlichsprachige Frage zum Code eines Projekts — Aufrufer/Aufgerufene, Imports, Symbolverlauf, letzte Änderungen oder eine Volltextsuche — und erhalte Dateipfade und exakte Zeilennummern zurück |

### Projekt-Feature-Baum

Genie verfolgt jedes Feature, jeden Bereich und jede Fähigkeit, die es in einem Projekt baut, als Baum — sichtbar im **Brain**-Tab des Projekts in der Web-App. Diese Tools erlauben einem externen KI-Client, diesen Baum zu lesen und zu pflegen. Lesen steht jedem offen, der das Projekt einsehen kann; ein Feature hinzuzufügen oder zu bearbeiten erfordert Projekt-Eigentümerschaft.

| Tool | Was es tut |
|---|---|
| `list_project_goals` | Liste den vollständigen Feature-Baum — jeden erfassten Feature-Bereich, jedes Feature und jede Aufgabe mit Status (`todo`, `in_progress`, `implemented`, `failed`, `blocked`, `abandoned`) |
| `get_project_goal_details` | Vertiefe ein Feature: seinen Status-Verlauf, die Code-Dateien, die es umsetzen, und (bei einem Feature-Bereich) wie weit es fertig ist |
| `create_project_goal` | Füge dem Baum ein Feature hinzu, um es zu erfassen — dies zeichnet nur die Absicht auf und startet keinen Build |
| `update_project_goal` | Benenne ein Feature um, ändere seine Abnahmekriterien oder aktualisiere seinen Status |
| `suggest_next_prompts` | Erhalte sofort nutzbare Prompt-Vorschläge dafür, was als Nächstes gebaut werden soll, basierend auf den offenen Features des Projekts |

### Bug-Tracking

Genie dedupliziert Bugs projektübergreifend: Taucht dieselbe Art von Bug erneut auf, wird die zuvor funktionierende Lösung wiederverwendet, statt erneut von vorn zu untersuchen. Mit diesen Tools kann ein externer KI-Client dieses System lesen und dort Bugs melden. Lesen steht jedem offen, der das Projekt einsehen kann; einen Bug zu melden erfordert Projekt-Eigentümerschaft.

| Tool | Was es tut |
|---|---|
| `get_known_issues` | Liste die erfassten Bug-Sichtungen eines Projekts — jeweils mit Quelle, Status, einer Zusammenfassung und dem projektübergreifenden Bug-Muster, dem sie zugeordnet wurden (falls vorhanden) |
| `report_known_issue` | Melde einen Bug in der Wissensdatenbank, damit er mit bekannten Mustern dedupliziert wird und seine spätere Lösung projektübergreifend wiederverwendet werden kann. Nur zur Nachverfolgung — startet nie einen Build. Nur der Projektinhaber kann dies aufrufen |
| `find_bug_solutions` | Durchsuche die gemeinsame Bug-Wissensdatenbank nach einer bewährten Lösung, indem du das Symptom in natürlicher Sprache beschreibst — projektübergreifend über alle Genie-Projekte, nicht nur die dieses Workspace. Nur lesend und weder auf ein Projekt noch einen Workspace beschränkt, da die Ergebnisse verallgemeinert und um projektspezifische Details bereinigt sind |

### Nutzer-Gedächtnis

Genies Workspace-KI merkt sich Dinge, die du im Chat über dich selbst erwähnt hast — deine Vorlieben, Tools, dein Team, deine Ziele — und bringt diesen Kontext automatisch in spätere Gespräche ein. Mit diesen Tools kann ein externer KI-Client dieses Gedächtnis durchsuchen oder löschen. Beschränkt auf den verbundenen Nutzer über alle seine Workspaces hinweg, nicht auf den aktuell verbundenen Workspace, da Erinnerungen ein nutzerbezogenes Konzept sind.

| Tool | Was es tut |
|---|---|
| `search_user_memory` | Durchsuche alles, was Genie sich über den verbundenen Nutzer gemerkt hat, sortiert nach Relevanz zu einer Anfrage, oder liste die zuletzt bekräftigten Erinnerungen, wenn keine Anfrage angegeben ist. Nur lesend |
| `forget_user_memory` | Lösche dauerhaft eine bestimmte gemerkte Tatsache über den verbundenen Nutzer anhand ihrer ID (ermittelt über `search_user_memory`) |

### Projekt-Speicher

Durchsuche und verwalte die Dateien in den Genie-Cloud-Speicher-Buckets eines Projekts. Nur der Projektinhaber bzw. die Projektinhaberin kann diese Tools verwenden.

| Tool | Was es tut |
|---|---|

| `create_project_storage_folder` | Erstelle einen Ordner in einem Speicher-Bucket |
| `delete_project_storage_items` | Lösche eine oder mehrere Dateien oder Ordner dauerhaft (das Löschen eines Ordners löscht alles darin) — erfordert `confirm_delete: true` |

Das Hochladen neuer Dateiinhalte ist über MCP nicht möglich — ein MCP-Tool-Aufruf transportiert nur JSON, keine Datei-Bytes. Lade Bilder und Videos über den Speicher-Tab des Projekts in der Web-App hoch, oder bitte die Genie-Workspace-KI darum.
</Note>

### Projekt-Prompt-Warteschlange

Trifft ein Folge-Prompt für ein Projekt ein, das bereits baut, reiht Genie ihn ein, statt ihn abzulehnen — siehe [Genie AI reiht den Prompt eines beschäftigten Projekts ein](/de/workspaces/overview#genie-ai-reiht-den-prompt-eines-beschäftigten-projekts-ein). Diese Tools lassen einen externen KI-Client diese Warteschlange direkt einsehen und verwalten.

| Tool | Was es tut |
|---|---|
| `list_prompt_queue` | Zeige die Prompt-Warteschlange eines Projekts: aktiv/pausiert (und warum), wartende Einträge, wann der nächste gesendet wird, und die letzte Historie |
| `pause_prompt_queue` | Pausiere die Warteschlange — es wird nichts Neues gesendet, bis sie fortgesetzt wird. Stoppt nie einen bereits laufenden Build |
| `resume_prompt_queue` | Setze eine pausierte Warteschlange fort. Startet die Abklingzeit ab jetzt neu, sodass ein Fortsetzen nie einen Schwall auslöst |
| `remove_prompt_queue_item` | Storniere einen noch wartenden, eingereihten Prompt |
| `reorder_prompt_queue_item` | Verschiebe einen wartenden Prompt an eine andere Position in der Warteschlange |
| `clear_prompt_queue` | Storniere jeden noch wartenden Prompt in der Warteschlange eines Projekts — erfordert `confirm_clear: true` |
| `set_prompt_queue_delay` | Ändere die Abklingzeit zwischen dem Abschluss eines Laufs und dem Senden des nächsten eingereihten Prompts |
| `send_next_queued_prompt_now` | Überspringe die verbleibende Wartezeit und sende den nächsten eingereihten Prompt, sobald das Projekt frei ist. Setzt auch eine pausierte Warteschlange fort |

### Workspace-Chat

Stelle Fragen an die Genie-Workspace-KI und durchsuche vergangene Gespräche. Jedes Tool hier wirkt auf jeden Chat im verbundenen Workspace, auch auf einen, den ein Teammitglied begonnen hat, nicht nur auf die eigenen des Aufrufers — `list_workspace_chats`/`search_workspace_chats` zeigen standardmäßig nur die eigenen Gespräche des Aufrufers, akzeptieren aber `scope: "workspace"`, um die aller anderen einzuschließen.

| Tool | Was es tut |
|---|---|
| `send_workspace_chat` | Stelle eine Frage zu deinem Workspace und erhalte eine KI-Antwort |
| `create_workspace_chat` | Starte oder setze einen dauerhaften Chat-Thread fort (in der Chat-Historie gespeichert) |
| `list_workspace_chats` | Letzte Gespräche mit Titel und Vorschau. Standardmäßig eigene Gespräche; übergib `scope: "workspace"`, um die von Teammitgliedern einzuschließen |
| `get_workspace_chat` | Liest das Transkript eines Gesprächs anhand seiner ID, auch das eines Teammitglieds — begrenzt auf standardmäßig die letzten 30 Turns (bis zu 100), jeder Turn auf 2.000 Zeichen gekappt. Prüfe `truncated`/`totalMessages`, bevor du annimmst, das ganze Gespräch zu haben |
| `search_workspace_chats` | Suche in vergangenen Nachrichten. Standardmäßig eigene Gespräche; übergib `scope: "workspace"`, um die von Teammitgliedern einzuschließen |
| `search_agent_run_traces` | Durchsuche per Volltextsuche die Ausführungsspur hinter den eigenen Genie-KI-Gesprächen des verbundenen Nutzers — die Begründung, jeden Tool-Aufruf und die endgültige Antwort, nicht nur den sichtbaren Chat-Text. Nützlich für Fragen wie „warum ist das vorhin fehlgeschlagen" oder „welcher Turn hat das Deploy-Tool aufgerufen" |
| `rename_workspace_chat` | Benenne jedes Gespräch im Workspace um, auch eines, das ein Teammitglied begonnen hat |
| `delete_workspace_chat` | Lösche jedes Gespräch im Workspace dauerhaft, auch eines, das ein Teammitglied begonnen hat, mitsamt allen Nachrichten. Unumkehrbar — prüfe das Feld `startedByUser` des Gesprächs zuerst, wenn du es nicht selbst begonnen hast |
| `get_project_chat_connection` | Zeigt, welcher Workspace-Chat der Hauptchat eines Projekts ist — derjenige, in dem die gesamte Arbeit an diesem Projekt stattfindet —, wie das aufgelöst wurde und welche anderen Projekte ihn sich teilen |
| `list_projects_sharing_chat` | Listet jedes Projekt auf, das einen bestimmten Workspace-Chat als Hauptchat nutzt |
| `connect_project_chat` | Macht einen Workspace-Chat zum Hauptchat eines Projekts. Behält eine bestehende Verbindung standardmäßig bei — übergib `replace: true`, um sie zu wechseln |

## Schnellbeispiele

### Projekt erstellen und nachfassen

```
Tool: create_project
{ "prompt": "A SaaS dashboard with auth, dark mode, and a billing page" }

→ Returns: deploymentUrl, slug

Tool: send_followup_prompt
{ "project_slug": "my-app-abc123", "prompt": "Add a CSV export button to the reports page" }
```

Der `create_project`-Aufruf startet den Build sofort und gibt die Deployment-URL zurück. Verwende `get_project_build_status`, um alles auf einmal abzufragen — Phase, Restzeit, Fortschritt und die Abschlusszusammenfassung, sobald sie fertig ist — oder `get_project_status` für eine leichtgewichtige Läuft/läuft-nicht-Prüfung.

### Auf eine frühere Version zurücksetzen

```
Tool: list_project_deployment_versions
{ "project_slug": "my-app-abc123" }

→ Returns: version ids, newest first

Tool: rollback_project_deployment
{ "project_slug": "my-app-abc123", "version": "42", "confirm_rollback": true }
```

Lasse `version` weg, um auf die zuletzt bereitgestellte vorherige Version zurückzusetzen. Der Rollback läuft im Hintergrund — frage `get_project_deployment_status` ab, um den Fortschritt zu sehen.

### Credit-Verbrauch diesen Monat prüfen

```
Tool: get_credit_usage
{ "range": "30d", "group_by": "project" }

→ Returns: { totalCredits: 142, byProject: [...] }
```

Admins können `scope: "workspace"` übergeben, um den Gesamtverbrauch aller Mitglieder einzusehen. Mitglieder können nur ihren eigenen Verbrauch abfragen. Mit `"sort": "credits_desc"` (oder `credits_asc`) wird die Aufschlüsselung nach Verbrauch sortiert, höchster Wert zuerst — oder `date_desc`/`date_asc`, wenn nach Tag gruppiert wird.

### Eine Frage zum Code eines Projekts stellen

```
Tool: query_project_code_graph
{ "project_slug": "my-app-abc123", "question": "who calls createCheckoutSession" }

→ Returns: matching symbols with file paths and exact line spans
```

### Neues Teammitglied einladen

```
Tool: invite_workspace_member
{ "role": "member", "max_uses": 1, "expires_in_days": 7 }

→ Returns: { inviteUrl: "https://www.genie-app.de/workspace/invite/abc123", role: "member" }
```
