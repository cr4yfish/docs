Genie supports the Model Context Protocol (MCP), an open standard that lets AI assistants call tools in external services. When you connect an MCP server to your workspace, every member can use those tools inside any project — without each person setting up their own credentials. A single workspace-level connection covers your whole team.

<Note>
MCP integrations are available on the **Teams** plan. If your workspace is on a lower tier, **Add a source** shows an upgrade prompt. Only **owners** and **admins** can add or remove servers.
</Note>

<Note>
Looking to message Genie from WhatsApp, Slack, or Microsoft Teams instead? That's a different kind of connection, added from the same **Add a source** — see [Genie on WhatsApp, Slack, and Teams](/workspaces/chat-channels).
</Note>

## Where integrations live

Every connection is on the Library's **Sources** page: open **Library** in the sidebar and press **All sources** on the **Sources** box. New ones are added with **Add a source** (the **+** on that box). **Settings → Integrations** no longer exists — old links and bookmarks land on Sources. See [Knowledge base](/workspaces/overview#knowledge-base).

The **Sources** page mirrors **Add a source**: what is connected is shown as tiles in the same groups, each with its state in words — *Active*, *Running*, *Paused*, *Needs attention*, or *Unknown* when it could not be checked. Whatever needs someone comes first in its group, and a line at the top counts those and filters to them. A group shows eight tiles until you press **Show all**, and each group heading leads to the picker. Press a tile to open that connection on the same page. Record syncs and [linked sources](#linked-sources) are listed there too, and **Add a source** marks what is already connected.

## Add a preset integration

Genie includes one-click presets for the most popular tools. Preset connections have their server URL, transport, and authentication type pre-configured — you just authorise and go.

<Steps>
  <Step title="Open Add a source">
    In the **Library**, press **+** on the **Sources** box.
  </Step>
  <Step title="Pick a service">
    **Add a source** lists every preset integration beside mail, files, business apps and chat apps, with a search. Click the tile for the service you want to connect; its guide opens with one **Connect** step.
  </Step>
  <Step title="Set a display name">
    The form pre-fills a display name (for example, "Linear"). The name becomes the tool prefix used by the AI — for example, `linear__create_issue`. Edit it if you need to distinguish multiple connections to the same service.
  </Step>
  <Step title="Connect the server">
    Click **Connect server**. For OAuth-based integrations, a second **Authorize** button appears on the server row — click it to start the OAuth flow and grant Genie access to your account. For Bearer token integrations, paste your API token into the **Bearer token** field before clicking **Connect server**.
  </Step>
  <Step title="Confirm the connection">
    After a successful OAuth authorisation, Genie brings you back to the Library's **Sources** page and tells you how it went. Tools from the connected server become available to all workspace members on their next conversation turn.
  </Step>
</Steps>

<Tip>
Each preset tile shows a short description of what it covers — for example, Linear covers "Issues, projects, cycles" and Stripe covers "Payments & customers". Use these descriptions to decide which integrations your team actually needs before adding them.
</Tip>

## Add a custom server

If the tool you need is not in the preset list, you can connect any MCP-compatible server manually.

<Steps>
  <Step title="Open Add a source">
    In the **Library**, press **+** on the **Sources** box.
  </Step>
  <Step title="Choose MCP server">
    Pick the **MCP server** tile (search for it, or find it under *Something else*).
  </Step>
  <Step title="Fill in the server details">
    Complete the form:

    - **Display name** — a label for this server. It becomes the tool prefix (for example, `mycrm__get_contacts`).
    - **Server URL** — the full URL of the MCP endpoint.
    - **Description** (optional) — a note for your team about what this server does.
    - **Transport** — choose **Streamable HTTP** (recommended for all servers built after March 2025) or **SSE** for older legacy servers.
    - **Authentication** — choose the auth type that matches your server (see below).
  </Step>
  <Step title="Connect the server">
    Click **Connect server**. If you chose OAuth2, click **Authorize** on the server row that appears to complete the OAuth flow. If you chose Bearer token, you will have already entered the token in the form.
  </Step>
</Steps>

## Connect any REST API

If a service has no MCP server, ask Genie AI in the workspace chat to connect it — *"Connect our Shopify shop"* or *"Connect our internal orders API"*. Genie AI writes down the API's **operations** (for example *List orders* and *Create order*) and asks you for the API key on a card of its own, so the key never passes through the model. The result is a **custom API** integration, listed with a **Custom API** badge, and each of its operations is available in three places:

- as a **step in the Genie Agents editor** — under **Your integrations** in the add-step list, one row per operation such as *Shop · List orders*. Its inputs appear as ordinary fields, with the raw JSON still available under **Advanced**;
- as a **tool of Genie AI itself**, so *"List my open orders"* works in chat;
- through the [Genie MCP Server](/workspaces/mcp-api), for external clients.

Open the integration's row to see its version, its operations (method, path, whether each reads or writes) and the first problem if a change was refused, or to press **Edit with Genie AI** or **Copy spec JSON**. Every change is saved as a new version, so an earlier one can be restored. Only owners and admins can add one, and the same [sharing and security rules](#security) as for any integration apply.

**Import operations from an OpenAPI document.** If the API publishes an OpenAPI 3 description, give Genie AI its link — *"Import the operations from https://api.example.com/openapi.json"*. Genie AI lists what the document offers, you pick the operations you want, and they are converted exactly as the document describes them (path, query and header inputs, JSON body) and saved as one new version. Operations that can't be converted faithfully are skipped, and Genie AI tells you why. An operation you already have is only overwritten when you ask for it. The document must be reachable over HTTPS on the public internet, and very large documents are read only up to a size limit.

## Authentication types

<Tabs>
  <Tab title="OAuth 2.1">
    Most preset integrations use OAuth 2.1. When you click **Authorize**, Genie discovers the service's authorisation server, dynamically registers a client, and completes the flow with PKCE. The resulting token is stored encrypted at the workspace level and refreshed automatically. No manual token management is required.

    If an OAuth connection expires or is revoked, click **Re-authorize** on the server row to restart the flow without losing your configuration.
  </Tab>
  <Tab title="Bearer token">
    Some services (including Stripe) use a static API key instead of OAuth. Paste the token into the **Bearer token** field when creating the server. The token is stored encrypted and is never returned to the browser after saving. All workspace members share this single token.

    To rotate the token, click the edit icon on the server row, enter the new token, and click **Save changes**. Leave the field blank to keep the existing token.
  </Tab>
  <Tab title="None">
    Some self-hosted or internal MCP servers do not require authentication. Select **None** as the auth type for these servers. Use this option only for servers on trusted private networks.
  </Tab>
</Tabs>

## Shared vs. personal connections

Most connectors are still one shared connection for the whole workspace — an admin connects it once, and every member's tools use that same credential, as described above. A few connectors need a personal account instead, because a shared credential wouldn't make sense there — **Microsoft 365**, **Gmail**, and **Google Drive**, for example, each need to reach one person's own mailbox or files rather than something shared. For those, an admin still adds the connector itself for the workspace, but each member then connects their own account from their side, and Genie's AI acts using that member's own connected account whenever it's that member talking to it, not a shared one.

If you haven't connected your own account yet, that connector simply isn't available to you until you do — Genie never falls back to someone else's connected account. If someone leaves the workspace, their personal connection is removed along with their membership. Only you can see that your own account is connected in a way that exposes your credentials; admins can see whether a connector is connected or not, but never the credential itself, even for connectors you've personally connected.

An owner or admin can switch a connector between shared and per-member later, from its **Edit** form ("Who signs in") — no need to remove it and add it again. Switching direction never carries an existing credential across: everyone connected under the old setting needs to (re)connect under the new one.

**Microsoft 365 also takes personal accounts.** When a member connects Microsoft 365, **Connect** asks whether it is a **Work or school account** or a **Personal Microsoft account** (Outlook.com, Hotmail, a personal OneDrive). A personal account reaches its own mail and OneDrive but not SharePoint sites, so SharePoint search isn't offered for it. Personal accounts only connect on per-member connectors that aren't pinned to a tenant — a shared connector, or one pinned to your organization's directory, accepts work or school accounts only.

## Sync your own mailbox

Every member can mirror their **own** Outlook or Gmail mailbox into the knowledge base, so Genie AI can answer from their mail. Open the Library's **Sources** page — your mailbox is under *Copied into the Library* — or add it with **Add a source → Mail**: it has one row per mailbox, each showing its state and the next step — **Connect** your account (an owner or admin has to add the integration first if it isn't there), **Start syncing**, **Pause**, **Resume**, **Try again** after a failed run, or **Stop**. Genie AI can show the same state, and starts, pauses or stops a sync only when you press the card it offers.

- **Only your own mail, last 90 days.** A sync reads the mailbox of whoever started it, never someone else's, and begins 90 days back. Mail folders aren't copied — every message becomes one document on a single shelf, and a message you move between folders stays the same document.
- **Private to you.** The mail lands in your own [personal area](/workspaces/overview#access-areas): only you can see it and what Genie makes from it — not other members, and not the workspace's owners and admins. An owner can read it only through a logged access grant you're told about, or after you leave, when the owners can read and change it or hand it to a successor.
- **Not everything is knowledge.** Newsletters and mailing lists, automated mail, calendar invitations and no-reply senders are skipped before anything is read, and show as *Not knowledge* in the sync's file list. Junk, Deleted Items, Drafts and similar folders are never read.
- **Stopping keeps what was filed.** The mail already read stays in your area; starting again files it a second time.

- **Time and cost, up front.** Before you start, the row says how many messages it will read, roughly how long that takes and what the import and each following month cost in credits. While it runs, it shows what is left, when it should be done and what the sync has cost so far. If a mailbox is too large to count completely, the figures say *at least*; if the count can't be finished in time it says so and offers **Try again** instead of guessing. A paused or stopped sync, or one with automatic sync off, says that new mail waits for a run to be started.

Mail is read into the knowledge base like any document, so it counts toward the same limits and the same credits as other synced files.

## Copy Slack and Teams channels into the Library

Decisions made in team chat can become knowledge like any document. **Add a source → Chat apps** lists each platform twice: **Slack** and **Microsoft Teams** let people [message Genie](/workspaces/chat-channels), while **Slack channels** and **Microsoft Teams channels** (tagged *Copies messages*) copy what people wrote to each other into the Library.

1. **Connect.** Nothing new to sign in to: Slack channels are read through the workspace's Slack install, Teams channels through your Microsoft 365 organization's consent. If a permission is missing, the guide names it and links to where you install or consent again.
2. **Choose.** Pick channels — search finds them by name, and a Teams channel also by its team — or take **All channels** (up to 200). Direct messages are never offered here — each member copies their own [into their personal area](#copy-your-own-slack-messages-and-teams-chats).
3. **Start.** The guide sums up what happens: the Slack app joins the public channels it reads, and everything read is filed for the **whole workspace**. The last 90 days are read first; after that the copy is kept current.

**What becomes a document.** A Slack channel files one document per day, each thread under its first message, plus the channel's canvases. A Teams channel files one document per thread, plus the team's Planner board. Each message names its author: a workspace member is shown with the name and address your workspace holds for them; anyone else keeps the name the platform shows.

**Status and control.** Once set up, the same place shows how far it is (channels, documents, last read), what's wrong and where to fix it, and the channels it holds. **Sync now**, **Pause**, **Resume**, **Change channels**, **Stop** (what was filed stays) and removing a single channel need permission to manage integrations; every member can see the status. The tile on the Sources page and the row on the Library overview say the same.

**Genie AI.** Ask *"is our Slack copied into the Library?"* and any member gets the answer. Adding or removing channels, pausing or stopping is a card that lists exactly which channels change, and runs only when you press it — never from a message, never over MCP. MCP clients can [read the status and the channel list](/workspaces/mcp-api#slack-and-teams-channels-read-only).

Reading channels uses no new kind of paid call; the documents it files cost what any synced document costs and count toward the same limits and [spend limits](/workspaces/governance#spend-limits).

## Copy your own Slack messages and Teams chats

Every member can also copy their **own** direct messages into their [personal area](/workspaces/overview#access-areas), so Genie AI can answer from them for that member. **Add a source → Chat apps** lists **My Slack messages** and **My Microsoft Teams chats** beside the channel sources.

1. **Connect.** The workspace has to be connected to Slack or Microsoft 365 first — if it isn't, the guide says an owner or admin connects it and links there. Then **Sign in** with your own account. The step says what is read, where it goes, who can see it, that the people you write with aren't asked, and how to stop. Tick *I understand who can see what is copied.* to continue.
2. **Choose** your conversations — one-to-one and group messages; on Slack also channels you're in, picked one by one — or take **All my direct messages**, which never sweeps in a channel.
3. **Start.** The last 90 days are read first, one document per conversation and day; after that the copy is kept current. The status offers **Sync now**, **Pause**, **Change conversations** and **Disconnect**, which asks twice, stops the sync and ends your sign-in — what was copied stays. If Slack or Microsoft stops accepting your sign-in, the row says **Sign in again**.

- **Only you can see them.** Your messages, the names of the people you write with, and what Genie makes from them are visible only to you. An owner can see them only through a logged access grant you're told about, or after you leave.
- **Nobody else drives your sync.** Owners and admins can't start, run, pause, stop or read the conversation list of anyone else's copy.
- **One switch for the workspace.** Whoever manages integrations finds **Members' own direct messages** in the channel guide, on by default. Off, nobody signs in or runs a copy; members can still pause, stop or disconnect, and what was copied stays. Beside it is a list of who copies their own messages — never what they read.
- **Genie AI** shows your own copies and starts, pauses, stops or disconnects them through a card. It can't sign in for you.

## Linked sources

A **linked source** is a system whose records are never copied into your workspace. Its data model — its classes, their properties and how they relate — joins your [knowledge model](/workspaces/overview#knowledge-model) as an area of its own, and its records are read live through the connection whenever someone opens them. It is the third way to bring data in:

| | Copied in | Looked up live | Linked |
|---|---|---|---|
| Example | A SharePoint folder, a record sync | A connector Genie AI asks | Captiva One |
| Where the data lives | In your workspace | In the source | In the source |
| In the knowledge model | Yes, as entities | No | Yes — as a locked area of its own |
| Browse it like any class | Yes | No | Yes |

The first linked source is **Captiva One**.

**Connect one.** Open **Library → Sources → Add a source** and pick the source. Paste the connection's address and key and press **Test connection** — nothing is saved yet. Then choose which of the source's classes join, each shown with its record count, and who sees their records: **Everyone in the workspace**, **Only owners and admins**, or people and teams you pick. **Start** connects it. Records start closed: until you open them, only owners and admins can read them. Genie AI can set a source up with you too — you type the key into a card, never into the chat.

**A locked area.** The source's classes and relations appear in an area named after it, marked with a plug and the source's name. Nobody can change that area here — not a manager, not Genie AI, not a draft: its classes, relations and records come from the source, so you change them there. Relations from your own classes may still point at a linked class.

**It follows the source.** Genie checks the source for changes regularly, and **Check for changes now** does it right away. New properties arrive on their own; a class the source stops offering is hidden. A class the source newly offers joins only when you tick it under **Change what joins**.

**Reading records.** A linked class's records open like any others. A line above them says when they were read and whether the source answered — *Read live from Captiva One · 12 s ago*, or that the source isn't answering and you are looking at what was read earlier. Linked records also appear on the Graph page and the entity map, a record lists the records that point at it, and a record's name in a text is recognised once the workspace has read it. Genie AI reads linked records through the same access rules as everyone else.

**Documents that stay in the source.** If the source keeps documents, Genie AI searches them beside your own and cites the passages it uses. The Library's Files search lists them in a section per source, and each source has a read-only folder among the Files page's places. Pressing a citation, a search hit or **Open document** opens the file straight away in the same viewer as your own PDFs, at the cited page with the passage highlighted. Genie AI can open such a document on the chat's canvas too. The Library's knowledge figures list each source's document count on its own row, never added to your workspace's own count.

**Processes and actions.** A source can publish the stages its records move through and grant the connection actions on them. A record's page then shows its stage, and each action as a button: a short form, a confirmation that lists exactly what is sent and says Genie can't undo it, and the result. A class with a process is listed under the Model's **Processes** too. Running an action needs permission to manage integrations and to edit the knowledge model, plus *Can change them* on the class's records. An action that would write a field you may not see is never offered. Genie AI runs an action only through a [confirmation card](/workspaces/overview#confirmation-cards).

**Pause, remove, forget.** A paused source is not asked anything. **Remove** hides its classes, archives its area and deletes its key and everything cached; nothing changes at the source. A removed source is listed under **Removed sources** and still counts toward the workspace's limit of linked sources (five by default) — connecting the same account again brings the same classes back. **Forget** gives that up for good: the area becomes an ordinary archived area you can reuse, and the place under the limit is free again.

**Who may do what.** Connecting, changing what joins, removing and forgetting need permission to manage integrations and to manage the knowledge model. Checking for changes, pausing and pasting a new key need permission to manage integrations. Everyone sees which area is linked and to what. Who sees a linked class's records is decided by its [records line](/workspaces/overview#share-an-item), as for any class.

MCP clients can [read linked sources](/workspaces/mcp-api#linked-sources-read-only).

## Manage connected servers

Each connected server appears as a row on the Library's **Sources** page, with a plain-language status — connected, ready, not connected yet, not working, per-member, or paused — instead of raw connection details. If the status is just a sign-in away, a **Connect** button sits right on the row rather than in a menu. From the row you can:

- **Enable / Disable** — temporarily turn a server off without removing it. Disabled servers do not provide tools to the AI.
- **Authorize / Re-authorize** — (OAuth servers only) start or restart the OAuth flow.
- **Edit** — change the display name, description, or bearer token.
- **Remove** — permanently disconnect the server and delete its credentials.

You can also do this from the chat: ask Genie AI to reconnect or repair an integration and it shows a card with the same buttons. See [Fix an integration from the chat](/workspaces/overview#fix-an-integration-from-the-chat).

## Security

<CardGroup cols={1}>
  <Card title="Encrypted at rest" icon="lock">
    All credentials — bearer tokens and OAuth tokens — are encrypted at rest. They are never returned to the browser after they are saved.
  </Card>
  <Card title="Audit trail" icon="shield-check">
    Every add, update, rotation, and removal of an MCP server is recorded in the workspace activity log, giving owners and admins a complete record of credential changes.
  </Card>
  <Card title="Role-based access" icon="users">
    Only owners and admins can add, edit, or remove servers. Other members can use the tools exposed by connected servers but cannot read or modify credentials, and never see a server's address.
  </Card>
</CardGroup>

<Warning>
Bearer tokens are shared across all workspace members. If a token is compromised, rotate it immediately using the **Edit** action on the server row and notify your team.
</Warning>
